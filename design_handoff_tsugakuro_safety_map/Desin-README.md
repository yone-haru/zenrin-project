# ハンドオフ: 通学路安全マップ UI

## 概要
出発地・目的地を指定してルート検索すると、ルート上の危険地点をピンで表示する Web アプリの UI 設計です。地図を全画面背景とし、検索パネル・ルート結果・危険箇所一覧・危険地点詳細を地図の上にフローティングカードとして重ねます。対象ユーザーは小学生の保護者および自治体職員です。

## このバンドルのファイルについて
このフォルダ内の HTML ファイルは **HTML で作成した「デザインリファレンス」（見た目と挙動を示すプロトタイプ）** であり、そのまま本番コードにコピーするものではありません。タスクは、このデザインを **対象コードベースの既存環境（要件定義書では React + TypeScript + Leaflet）で再現すること** です。既存のパターン・ライブラリに沿って実装してください。環境がまだ無い場合は、要件定義書のスタック（React + TypeScript + Leaflet / FastAPI）に従ってください。

- `通学路安全マップ.dc.html` … 3 画面すべての見た目と挙動を 1 ファイルで再現したインタラクティブなデザインリファレンス（状態遷移：ランディング → ルート結果 → 危険地点詳細モーダル）。**Design Component 形式**（独自ランタイム）で書かれているため、コードをそのまま流用するのではなく、見た目・寸法・色・挙動の参照元として使ってください。
- `要件定義書_通学路危険動線解析システム.md` … バックエンド/API/データモデルを含む実装仕様書。

## フィデリティ
**ハイファイ（hifi）**。最終的な色・タイポグラフィ・余白・角丸・影・インタラクションを含む高精度モックです。UI は本書の数値どおりにピクセル単位で再現してください。地図描画は Leaflet（OSM タイル）で実装し、本デザインの SVG 地図は「色・ピン・ルートラインの見た目の見本」として参照してください。

## 画面 / ビュー

### 画面1: ランディング（検索前）
- **目的**: 出発地・目的地を入力してルート検索を開始。
- **レイアウト**: 全画面の明るい地図が背景。左上に検索カード、下中央にヒントのピル。
- **検索カード**（左上 top/left 16px、幅 360px、padding 16px）:
  - ヘッダー: 盾アイコン（青 `#2563eb`、中にチェック）+ 「通学路安全マップ」(18px/700)
  - 「出発地」入力: 左に緑のドット（11px、`#16a34a`、3px の薄リング）、placeholder「出発地を入力」。入力背景 `#f1f5f9`、高さ 44px、角丸 10px。
  - 「目的地」入力: 左に赤いピンアイコン（`#ef4444`）、placeholder「目的地を入力」。
  - 2 入力の右側中央に入れ替えボタン（↕、丸 28px、白、薄い枠線）。クリックで出発地⇄目的地を入れ替え。
  - 全幅ボタン「ルートを検索」（高さ 46px、`#2563eb`、白文字 15px/700、左に虫眼鏡アイコン）。
- **下中央ピル**: 白、角丸 24px、padding 10px/18px。ピンアイコン + 「地図をクリックして地点を指定できます」(13px/500/`#64748b`)。

### 画面2: ルート検索後（メイン状態）
- **目的**: ルートと危険箇所を確認する。
- **地図上の表示**:
  - 青いルートのポリライン（`#2563eb`、太さ 6px、白いケーシング 11px、丸端/丸結合）。
  - 出発に緑「A」マーカー、到着に赤「B」マーカー（しずく型ピン、白丸に頭文字、ドロップシャドウ）。
  - ルート上に危険ピン 3 個（白縁の丸 + 危険度色の丸 + 白い数字）。赤「5」/ 橙「3」/ 黄「2」。クリックで詳細モーダルを開く。選択中はピンが 1.18 倍に拡大し、同色のリングが付く。
- **検索カード**: 画面1と同じ。入力は入力済み（「長崎市立〇〇小学校」/「〇〇町1-2-3」）。
- **ルート情報カード**（検索カード下、top 240px / left 16px、幅 360px）:
  - ラベル「ルート情報」
  - 行: 🚶 距離（例 1.2km）/ ⏱ 所要（約15分）/ 右に赤バッジ「危険箇所 3件」(`#fee2e2`背景・`#dc2626`文字)。アイコンはインライン SVG（emoji ではない）。
- **危険箇所一覧パネル**（右、top/right/bottom 16px、幅 320px、全高、スクロール可）:
  - タイトル「危険箇所一覧」+ 件数バッジ「3件」(`#fee2e2`/`#dc2626`、丸ピル)
  - 各項目カード: 左に 5px の危険度色ボーダー、危険度スコアの丸バッジ（34px、危険度色、白/濃色数字）、タイトル（例「本河内交差点」14px/700）、出発からの距離（11px/`#94a3b8`）、右にシェブロン。下部にタグチップ（例「歩道なし」「事故多発」、11px/600、`#f1f5f9`背景）。
  - クリックで対応ピンをハイライト＋詳細モーダルを開く。選択中は背景 `#eff4ff`、枠 `#bfd3ff`。

### 画面3: 危険地点詳細（画面2上のモーダル）
- **目的**: 1 箇所の危険要因・事故データ・道路情報を確認する。
- 背景は画面2を `rgba(15,23,42,0.45)` で暗転。中央にモーダルカード（幅 480px、角丸 16px、白）。フェードイン + 下からのスライド（modalIn .25s）。
- **構成**（上から）:
  - 上端に危険度色の帯（高さ 8px）。
  - 右上に × クローズ（丸 32px、`#f1f5f9`背景）。
  - ラベル「危険度」+ 大きなスコア数字（52px/900、危険度色）+ 5 個の丸（スコア分が危険度色、残りは `#e5e7eb`）。

  - セクション「危険要因」: チップ（危険度色の文字 + 淡色背景）。例「歩道なし」「過去事故3件」「幹線道路との交差」。

  - セクション「道路情報」: 枠付きの 2 行 — 「道路種別 / 幹線道路」「歩道 / なし」。
  - 下部ボタン: 「閉じる」（ゴースト、枠線 `#e2e8f0`）+ 「地図で確認」（青プライマリ）。

## サンプルデータ（デザイン中の危険地点）
1. `本河内交差点` — スコア5（赤）/ タグ: 歩道なし・事故多発 / 出発から350m / 要因: 歩道なし・過去事故3件・幹線道路との交差 / 事故: 過去5年間で3件 / 道路種別: 幹線道路 / 歩道: なし
2. `桜町歩道橋前` — スコア3（橙）/ タグ: 見通し不良・横断多い / 出発から720m / 要因: 見通し不良・横断歩道の間隔が広い / 事故: 過去5年間で1件 / 道路種別: 補助幹線道路 / 歩道: 片側のみ
3. `栄町2丁目角` — スコア2（黄）/ タグ: 生活道路・車両通行 / 出発から980m / 要因: 車両の通行が多い / 事故: 過去5年間の事故報告なし / 道路種別: 生活道路 / 歩道: あり

> 実装では上記はダミー。実データは API（`POST /api/route` の `hazard_points`）から取得します。詳細は要件定義書を参照。

## インタラクション & 挙動
- 「ルートを検索」: 入力済みの出発地/目的地で `POST /api/route` を実行 → 地図にルートライン＋危険ピン描画、ルート情報カードと危険箇所一覧を表示。検索中はローディング表示。
- 入れ替えボタン: 出発地⇄目的地を入れ替え。
- 危険ピン / 一覧カードのクリック: 該当ピンを選択ハイライト（1.18倍＋リング）し、詳細モーダルを開く。
- モーダル: × / 「閉じる」 / 背景クリックで閉じる。「地図で確認」は閉じて該当地点を選択状態にする。
- 地図クリック: 地点（出発地・目的地）を直接指定（要件定義書の `/api/geocode` と併用）。
- アニメーション: カード/パネルは fadeIn .3s、モーダルは modalIn .25s、ピン拡大は transform .18s。

## 状態管理
- `screen`: `'landing' | 'route'`
- `origin` / `dest`: 入力テキスト（および座標）
- `selectedId`: 選択中の危険地点 ID（ピンのハイライト用）
- `modalId`: 詳細モーダルを開いている危険地点 ID（null で閉）
- データ取得: `POST /api/route`（ルート＋危険地点）、`GET /api/geocode`（住所→座標）。型は要件定義書の `RouteResponse` / `HazardPoint` に準拠。

## アセット
- アイコンはすべてインライン SVG（盾・虫眼鏡・入れ替え・徒歩・時計・警告三角・ピン・シェブロン・×）。外部画像なし。emoji は使用していません。
- フォント: Google Fonts の `Noto Sans JP`。
- 地図: 本デザインは SVG で簡易表現。実装は Leaflet + OSM タイルで置き換え、ルート/ピン/マーカーの色とスタイルのみ本デザインに合わせる。
